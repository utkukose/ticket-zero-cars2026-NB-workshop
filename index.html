WHY THIS MATTERS

Assistants that act turn a message into an instruction

AI assistants are moving from answering questions to taking actions: reading tickets, looking up records, issuing credits, sending messages. That means a message is no longer only a message. It can be an instruction the assistant obeys. Prompt injection is the name for that problem, and it is the single most important security idea for anyone building with or relying on AI assistants today. This workshop makes it tangible by letting the room do it, then defend against it.

HOW IT PLAYS

Two phases

ATTACK

Break the agent

Write a ticket to SUPPORTBOT and watch its console react step by step. Climb a ladder of objectives: map the agent's hidden tools, pry out a confidential code, push a credit past policy, exfiltrate another customer's data, and plant an instruction that runs later. Every capture shows why it matters in a real system.

DEFENSE

Defend the agent

Switch sides. Each round shows two possible next attacks. Arm up to two architectural controls and commit before the wave fires. The control that best fits scores full; the weak phrase-blocklist scores nothing. No single control stops everything without turning away a real customer, which is the point.

ATTACK PHASE

Capture the flags

Map the agent
Enumerate the agent's tools, including the undocumented ones.
Loose lips
Make the agent disclose an internal secret through authority framing.
Free money
Issue a credit beyond policy, or to an account that is not yours.
Postman
Exfiltrate another customer's record through an external tool.
Sleeper
Plant an instruction in a profile field and make the agent run it on lookup.
Kill chain
Chain reconnaissance, disclosure, and exfiltration into one breach.

DEFENSE PHASE

Arm the defenses

Separate read from act
Treat the ticket and retrieved text as data only. No action is derived from it.
Limit connections
Disconnect external tools so nothing can leave the system.
Human in the loop
Queue consequential actions for a person to approve.
Check the output
Scan anything leaving the agent for secrets and personal data.
Block bad phrases
A blocklist that is easy to slip past. Included to be defeated.

RUN YOUR OWN

Self-hosting

Ticket Zero is one small server with no external dependencies and no external AI calls. The agent is a deterministic simulation, so the game is reproducible and runs offline. Set two secrets and start it with Docker:

git clone https://github.com/utkukose/ticket-zero-cars2026-NB-workshop.git
cd ticket-zero-cars2026-NB-workshop
# edit TZ_SECRET and TZ_PRESENTER_KEY in docker-compose.yml, then:
docker compose up -d --build

Players open /, the room watches /wall, and the facilitator drives /control. The facilitator guide walks through a full session, and the primer covers every technique and defense with references.
